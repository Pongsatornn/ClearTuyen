# 🔐 AUTH_SETUP — เปิดระบบล็อกอินจริง (Email + Password และ Google)

เอกสารนี้คือ **ส่วนที่โค้ดทำแทนไม่ได้** — การกดตั้งค่าในหน้า Supabase Dashboard และ Google Cloud Console ซึ่งเป็นบัญชีของคุณ Claude เข้าไม่ได้

> ฝั่งโค้ดเสร็จแล้วทั้งหมด: ฟอร์มสมัคร/เข้าสู่ระบบด้วยอีเมล + ปุ่ม Google อยู่ใน `components/AuthDialog.tsx` เปิดจาก 3 จุดในแอปผ่าน `startSignIn()` (ปุ่มมุมบน, แผงเมนูที่บันทึกไว้, กล่องที่เด้งตอนกดหัวใจ)
>
> **ใช้เวลาประมาณ 10 นาทีสำหรับขั้นที่ 1–5** ส่วน Google (ขั้นที่ 6) ทำทีหลังเมื่อไหร่ก็ได้

> 🚨 **ถ้าเริ่มขั้นที่ 3 แล้วต้องทำให้จบถึงขั้นที่ 4.5 ในคราวเดียว** — ระหว่างนั้นทั้งเครื่องที่พัฒนาและ**เว็บจริงบน Vercel** จะบันทึก/โหลดเมนูไม่ได้ อ่านเหตุผลในสองหัวข้อถัดไป

---

## ⚠️ อ่านก่อน: ขั้นที่ 3 กับ 4 ต้องทำติดกัน

ตอนนี้ RLS policy ในฐานข้อมูลเป็นของ **role `anon`** อย่างเดียว (ดู `supabase/migration.sql`) พอผู้ใช้ล็อกอินจริง Supabase client จะเริ่มส่ง JWT ที่มี **role `authenticated`** ไปแทน — ซึ่ง**ไม่ตรงกับ policy ไหนเลย** ผลคือ RLS ปฏิเสธทุกคำสั่ง อ่านก็ไม่ได้ บันทึกก็ไม่ได้

แปลว่า "เปิด auth จริงแต่ยังไม่รัน migration" = แอปพังหนักกว่าเดิม ทำสองขั้นนี้ในคราวเดียวกันเสมอ

## ขั้นที่ 1 — เปิดการล็อกอินด้วยอีเมล

**Supabase Dashboard → Authentication → Sign In / Providers → Email**

1. เปิดสวิตช์ **Enable Email provider**
2. **ปิด "Confirm email"** ← สำคัญมาก
3. ปล่อย **Minimum password length** ไว้ที่ค่าเริ่มต้น `6` (ตรงกับที่ฟอร์มเช็คไว้ใน `AuthDialog.tsx`)
4. กด Save

### ทำไมต้องปิด Confirm email

SMTP ที่ Supabase แถมมาให้ในแพ็กเกจฟรีมีข้อจำกัดที่คนส่วนใหญ่ไม่รู้จนกว่าจะเจอเอง:

- ส่งได้ประมาณ **2 ฉบับต่อชั่วโมง** เท่านั้น
- ส่งได้เฉพาะไปยัง**อีเมลของสมาชิกในทีมของโปรเจกต์**เท่านั้น — อีเมลคนอื่นถูกทิ้งเงียบๆ

ถ้าเปิด Confirm email ไว้โดยไม่ได้ต่อ SMTP ของตัวเอง คนที่กดสมัครจะได้หน้า "ส่งลิงก์ยืนยันไปแล้ว" แล้วรออีเมลที่ไม่มีวันมาถึง

โค้ดรองรับทั้งสองแบบอยู่แล้ว (`signUpWithEmail()` คืน `'signed-in'` หรือ `'needs-confirmation'` แล้ว `AuthDialog` แสดงคนละหน้าจอ) — วันไหนต่อ SMTP เองแล้วจะกลับมาเปิดก็ได้ ดู[หัวข้อท้ายเอกสาร](#ทีหลัง-เมื่อไหร่ควรเปิด-confirm-email-กลับ)

## ขั้นที่ 2 — ตั้งค่า URL

**Authentication → URL Configuration**

| ช่อง | ใส่อะไร (ค่าจริงของโปรเจกต์นี้ copy ไปวางได้เลย) |
|---|---|
| **Site URL** | `https://fridge-menu-eta.vercel.app` |
| **Redirect URLs** | กด Add URL 2 ครั้ง ใส่ `http://localhost:3000/**` และ `https://fridge-menu-eta.vercel.app/**` |

ถ้าไม่ใส่ Redirect URLs ให้ครบ Supabase จะปฏิเสธการเด้งกลับหลังล็อกอิน Google (และลิงก์ยืนยันอีเมล ถ้าใช้) — อาการคือเด้งไปแล้วเจอหน้า error แทนที่จะกลับมาที่แอป

**สามเรื่องที่พลาดกันบ่อย:**

- **`/**` ท้าย URL ห้ามลืม** — ใส่ `https://fridge-menu-eta.vercel.app` เฉยๆ จะ match แค่หน้าแรกเป๊ะๆ ส่วน `/**` ครอบทุก path
- **Site URL เป็นแค่ปลายทางสำรอง** ตอนที่แอปไม่ได้ระบุมาเอง ซึ่งแอปนี้ระบุเสมอ (`redirectTo: window.location.origin` ใน `lib/supabase.ts`) ใส่โดเมน production ไว้จึงไม่กระทบการ dev บนเครื่อง ตราบใดที่ `localhost:3000` อยู่ในลิสต์ Redirect URLs
- **ถ้า `npm run dev` ไปเปิดพอร์ตอื่น** (เช่น 3001 เพราะ 3000 ไม่ว่าง) ล็อกอินจะถูกปฏิเสธ — ปิดตัวที่แย่งพอร์ต 3000 หรือเพิ่ม `http://localhost:3001/**` ด้วย

> **ทำไมไม่ใส่ `fridge-menu-pst7.vercel.app`:** โดเมนนั้นเด้งเข้า Vercel SSO (ต้องล็อกอิน Vercel ก่อนถึงจะเข้าได้) ไม่ใช่ URL สาธารณะ — ตัวที่คนนอกเข้าได้จริงคือ `-eta` เท่านั้น
>
> ถ้าอยากให้ preview deploy ล็อกอินได้ด้วย เพิ่ม `https://fridge-menu-*-pst7.vercel.app/**` เข้าไปได้ (ไม่จำเป็น — ตอนนี้ preview ถูก SSO ของทีมกั้นอยู่แล้ว)

## ขั้นที่ 3 — รัน migration

**SQL Editor → New query →** copy ทั้งไฟล์ [`supabase/migration_auth.sql`](../supabase/migration_auth.sql) ไปวาง → **Run**

ไฟล์นี้ทำ 4 อย่าง:

1. **ลบเมนูเก่าที่บันทึกไว้สมัยยังไม่มี auth จริงทิ้งทั้งหมด** ⚠️ — แถวพวกนั้นมี `user_id` เป็น UUID ที่แต่งขึ้นในเบราว์เซอร์ ไม่มีตัวตนใน `auth.users` จึงผูก foreign key ไม่ผ่านและไม่มีทางรู้ว่าเป็นของใคร
   ถ้าอยากเก็บไว้ก่อน: Table Editor → `saved_recipes` → Export CSV
2. เปลี่ยนคอลัมน์ `user_id` จาก `text` เป็น `uuid` แล้วผูก foreign key ไปที่ `auth.users`
3. เปลี่ยน policy จาก `to anon (true)` เป็น `to authenticated` + เช็ค `auth.uid()` — ตั้งแต่นี้ไปคนอื่นอ่านเมนูของเราไม่ได้จริงๆ ระดับฐานข้อมูล ไม่ใช่แค่ฝั่งแอปไม่แสดง
4. เปิดสิทธิ์ลบเมนูของตัวเอง (ปุ่มถังขยะใน "เมนูที่บันทึกไว้" ต้องใช้อันนี้)

## ขั้นที่ 4 — ปิดโหมดจำลอง

แก้ [`.env.local`](../.env.local):

```
NEXT_PUBLIC_MOCK_AUTH=0
```

แล้ว **รีสตาร์ท dev server** (`Ctrl+C` แล้ว `npm run dev` ใหม่) — Next.js แทนค่า `NEXT_PUBLIC_*` ตอน build ไม่ใช่ตอนรัน แก้ไฟล์เฉยๆ โดยไม่รีสตาร์ทจะไม่มีอะไรเปลี่ยน

หลังจากนี้โหมดจำลองใช้ไม่ได้อีกแล้วถาวร (ต่อให้เปิดกลับเป็น `1`) เพราะ RLS ในขั้นที่ 3 บังคับให้ `user_id` ต้องมีตัวตนจริงใน `auth.users` ส่วนบัญชีจำลองเป็น UUID ที่แต่งขึ้นเอง — ตั้งใจให้เป็นแบบนั้น ไฟล์ `lib/mockAuth.ts` เขียนเตือนไว้ตั้งแต่แรกแล้ว

## ⚠️ ขั้นที่ 4.5 — เว็บที่ deploy อยู่บน Vercel ก็ต้องแก้ด้วย

**ข้ามขั้นนี้ไม่ได้ถ้ายังอยากให้ https://fridge-menu-eta.vercel.app ใช้งานได้**

ตอนนี้เว็บ production เปิดโหมดจำลองอยู่ (`NEXT_PUBLIC_MOCK_AUTH=1` ตั้งไว้บน Vercel) ซึ่งอาศัยว่าฐานข้อมูลยังเป็น policy ชุด `to anon` — **พอรัน `migration_auth.sql` ในขั้นที่ 3 เว็บตัวจริงจะบันทึก/โหลดเมนูไม่ได้ทันที** ไม่ใช่แค่เครื่องที่พัฒนาอยู่

ทำสามอย่างนี้ให้ครบ:

```bash
# 1. เปลี่ยน env var บน Vercel เป็น 0
#    (ค่า NEXT_PUBLIC_* ต้องใส่แบบ --no-sensitive ไม่งั้น Vercel ปฏิเสธ)
cd fridge-menu
npx vercel env rm NEXT_PUBLIC_MOCK_AUTH production
npx vercel env add NEXT_PUBLIC_MOCK_AUTH production --no-sensitive --value 0

# 2. deploy ใหม่ — โปรเจกต์นี้ไม่ได้ผูกกับ Git repo การ push ไม่ทำให้เว็บอัปเดต
npx vercel deploy --prod --yes
```

3. เช็คว่าขั้นที่ 2 ใส่ `https://fridge-menu-eta.vercel.app/**` ไว้ใน Redirect URLs แล้วจริง — ถ้าลืม ล็อกอินบนเว็บจริงจะถูกปฏิเสธทั้งที่บนเครื่องตัวเองใช้ได้ปกติ

> **ผลข้างเคียงที่ต้องรู้ล่วงหน้า:** ตั้งแต่นี้ไปคนที่เข้าเว็บจะบันทึกเมนูไม่ได้จนกว่าจะสมัคร/ล็อกอินเอง — ต่างจากเดิมที่กดเลือกบัญชีจำลองแล้วใช้ได้เลย ซึ่งก็เป็นเรื่องที่ตั้งใจ เพราะโหมดจำลองแปลว่าทุกคนเห็นเมนูของกันและกันหมด

## ขั้นที่ 5 — ทดสอบ

ไล่ตามนี้ทีละข้อ ถ้าผ่านครบแปลว่าใช้ได้จริง:

- [ ] ปุ่มมุมบนขวาเขียนว่า **"เข้าสู่ระบบ"** และ**ไม่มี**ป้ายส้ม "โหมดจำลอง" แล้ว
- [ ] กดปุ่มนั้น → กล่องเข้าสู่ระบบเด้งขึ้นมา มีฟอร์มอีเมล/รหัสผ่าน (ยัง**ไม่มี**ปุ่ม Google — ซ่อนไว้จนกว่าจะทำขั้นที่ 6)
- [ ] กด "สมัครสมาชิก" → กรอกอีเมล/รหัสผ่าน (6 ตัวขึ้นไป) → เข้าสู่ระบบสำเร็จทันที กล่องปิดเอง อีเมลขึ้นที่มุมบน
- [ ] Dashboard → **Authentication → Users** เห็นบัญชีที่เพิ่งสมัครโผล่ขึ้นมาจริง
- [ ] หาเมนู → กดหัวใจ → **Table Editor → `saved_recipes`** เห็นแถวใหม่ และ `user_id` ตรงกับ id ในหน้า Users
- [ ] เปิด "เมนูที่บันทึกไว้" → เห็นเมนูนั้น → กดถังขยะ → ลบออกจริง (ไม่กลับมาตอนรีเฟรช)
- [ ] ออกจากระบบ → เปิด "เมนูที่บันทึกไว้" → ขึ้นชวนล็อกอิน ไม่เห็นเมนูของใครเลย
- [ ] สมัครบัญชีที่สองด้วยอีเมลอื่น → **ต้องไม่เห็นเมนูของบัญชีแรก** (ข้อนี้คือข้อที่พิสูจน์ว่า RLS ทำงาน)
- [ ] กรอกรหัสผ่านผิด → ขึ้นข้อความไทย "อีเมลหรือรหัสผ่านไม่ถูกต้อง" ไม่ใช่อังกฤษ

## ขั้นที่ 6 — เพิ่ม Google (ทำทีหลังก็ได้)

**ตอนนี้ปุ่ม Google ถูกซ่อนไว้** (`NEXT_PUBLIC_GOOGLE_AUTH=0` ใน `.env.local`) กล่องเข้าสู่ระบบจึงเหลือแค่ฟอร์มอีเมล/รหัสผ่าน
— เพราะถ้าโชว์ปุ่มไว้ทั้งที่ provider ยังปิด คนกดจะเด้งไปเจอ JSON ดิบเต็มหน้าจอ ("หน้าขาวมีโค้ดฝรั่ง" ใน `USER_REVIEW.md`)

ทำขั้นนี้จบแล้วค่อยเปิดปุ่มกลับมาที่ **ขั้นที่ 6.5** ด้านล่าง ทุกอย่างในนี้ฟรีทั้งหมด

### 6.1 หา callback URL ของโปรเจกต์คุณก่อน

**Supabase → Authentication → Sign In / Providers → Google** จะมี **Callback URL** ให้ copy หน้าตาแบบนี้:

```
https://<project-ref>.supabase.co/auth/v1/callback
```

### 6.2 สร้าง OAuth client ที่ Google

ไปที่ [console.cloud.google.com](https://console.cloud.google.com) แล้ว:

1. สร้างโปรเจกต์ใหม่ (หรือใช้อันเดิม)
2. **APIs & Services → OAuth consent screen**
   - User Type: **External**
   - กรอก App name, User support email, Developer contact — แค่นี้พอ ไม่ต้องใส่ logo หรือ domain
   - **Test users:** ใส่อีเมล Google ของคุณเอง ⚠️ ตราบใดที่ยังไม่กด Publish app จะล็อกอินได้**เฉพาะอีเมลในลิสต์นี้เท่านั้น** คนอื่นกดแล้วเจอหน้า "Access blocked" — จุดนี้คือที่คนติดกันบ่อยที่สุด
3. **APIs & Services → Credentials → Create Credentials → OAuth client ID**
   - Application type: **Web application**
   - **Authorized redirect URIs:** วาง Callback URL จากข้อ 6.1 ลงไป (ต้องตรงเป๊ะทุกตัวอักษร)
   - กด Create → จะได้ **Client ID** กับ **Client Secret**

### 6.3 เอามาใส่ Supabase

กลับไป **Supabase → Authentication → Sign In / Providers → Google** → เปิดสวิตช์ Enable → วาง Client ID และ Client Secret → Save

### 6.4 เปิดปุ่ม Google ในแอป

แก้ [`.env.local`](../.env.local) แล้วรีสตาร์ท dev server:

```
NEXT_PUBLIC_GOOGLE_AUTH=1
```

และถ้าจะให้เว็บจริงมีปุ่มด้วย ต้องตั้งบน Vercel + deploy ใหม่ (ค่า `NEXT_PUBLIC_*` ถูกฝังตอน build):

```bash
cd fridge-menu
npx vercel env add NEXT_PUBLIC_GOOGLE_AUTH production --no-sensitive --value 1
npx vercel deploy --prod --yes
```

### 6.5 ทดสอบ

- [ ] เปิดกล่องเข้าสู่ระบบ → **เห็นปุ่ม Google** โผล่เหนือฟอร์มอีเมล
- [ ] กดปุ่ม "เข้าสู่ระบบด้วย Google" → เด้งไปหน้าเลือกบัญชี Google → กลับมาที่แอปโดยล็อกอินแล้ว
- [ ] ถ้าใช้อีเมล Google ตัวเดียวกับที่เคยสมัครด้วยรหัสผ่านไว้ → **ต้องได้บัญชีเดิม เห็นเมนูเดิม** (Supabase เปิด "Link accounts with same email" ไว้เป็นค่าเริ่มต้น)

## ทีหลัง: เมื่อไหร่ควรเปิด Confirm email กลับ

ตอนจะให้คนนอกใช้จริง — เพราะถ้าไม่ยืนยันอีเมล ใครก็สมัครด้วยอีเมลของคนอื่นได้

แต่ต้องต่อ SMTP ของตัวเองก่อน (Dashboard → Project Settings → Authentication → SMTP Settings) ตัวเลือกที่ฟรี:

| บริการ | โควตาฟรี |
|---|---|
| **Resend** | 3,000 ฉบับ/เดือน (100/วัน) |
| **Brevo** | 300 ฉบับ/วัน |
| **Mailgun / SendGrid** | มีแพ็กฟรีแต่เงื่อนไขเปลี่ยนบ่อย เช็คก่อนใช้ |

พอต่อ SMTP แล้วค่อยกลับไปเปิด Confirm email ที่ขั้นที่ 1 — โค้ดรองรับอยู่แล้ว ไม่ต้องแก้อะไรเพิ่ม

## ข้อควรรู้เรื่องแพ็กเกจฟรีของ Supabase

- **50,000 monthly active users** — เกินกว่าที่โปรเจกต์นี้จะแตะถึงมาก
- **โปรเจกต์จะถูก pause ถ้าไม่มีการใช้งาน 7 วัน** — ปลุกเองได้ที่หน้า Dashboard แต่ระหว่างที่หลับอยู่แอปจะบันทึก/โหลดเมนูไม่ได้ (ฟีเจอร์หาเมนูยังใช้ได้ปกติเพราะไม่แตะฐานข้อมูล)
- จำกัด 2 โปรเจกต์ที่ active พร้อมกันต่อหนึ่งบัญชี
